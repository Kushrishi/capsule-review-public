# Red-lesion data feasibility — index-only acquisition gate

**Status:** Source candidate, not yet accepted as an independent pathology benchmark. The post-s288/s280/s284 cumulative transfer upper bound is **412,500,050 bytes** out of 536,870,912 bytes (512 MiB). This gate permits at most **4 MiB** of official ZIP **index** transfers; it neither extracts nor retains medical images.

## Most relevant options

- **Galar v2**: best current frame-wise pathology annotation source for Capsule Review. The pilot's saved images are sparse. Dense Galar `7z` source archives are tens of GB and solid-compressed, beyond the remaining acquisition budget. Preserve the 1–10 exploratory runs and the authors' unopened 61–80 holdout.
- **Red Lesion Endoscopy Dataset** ([INESC TEC](https://rdm.inesctec.pt/dataset/nis-2018-003), DOI 10.25747/H131-XH63): Set 1 is **3,295 nonsequential** images with red-lesion masks. Set 2 is described by the publisher as **600 sequential** 320×320 capsule frames. The publisher lists CC BY-SA and a ~451-MB combined ZIP. Academic references disagree about public availability of **Set 2 frame-level labels**; the archive must be inspected, not inferred from study-level statistics.
- **Kvasir-Capsule** ([Simula](https://datasets.simula.no/kvasir-capsule/)): 47,238 medically annotated still frames, 43 matching full videos, but **only selected frames** are labelled. Its labelled-image ZIP is ~521 MB and labelled-video ZIP ~32.2 GB. Research/education permissions do not imply unrestricted clinical/commercial use.
- **WCEbleedGen v2** ([Zenodo](https://zenodo.org/records/10156571)): ~166 MB of curated blood/nonblood images and localization labels, compiled from other sources; **not** a complete time-labelled examination and larger than our remaining source budget. Not an independent patient-level external test without provenance/overlap review.
- **Rhode Island**: completed 3-study anatomy-only replication. Its labels are **not pathology truth**, and the exploratory change-selection advantage did not consistently repeat. Do not enlarge this anatomy study to answer a pathology question.

## Index-only check

`python scripts/probe_red_lesion.py --output /tmp/red-lesion-index.json` requests only exact HTTP **206** byte ranges of the official publisher ZIP. It refuses a full HTTP **200** response and caps the whole index probe at **4 MiB**. The output records actual archive length, transferred bytes and grouped compressed/uncompressed sizes, possible masks and encryption flags; it never treats a file extension or a path named `B` as validated pathology ground truth. The publisher exposes a dataset-access password on its public page; index discovery does not require extracting password-protected content.

**Decision to extract later:** only if exact named Set 2 files and accompanying usable reference labels/masks are present, permissions and access are verified, and the estimated total physical transfer is below the original **remaining cumulative** allowance after accounting for the probe. A subsequent extraction requires source-member CRC/SHA-256, full frame-index and annotation alignment verification. Any medically useful result must distinguish red-lesion presence from Galar `blood`, and must not claim clinical lesion sensitivity without appropriately defined reference events. If Set 2 labels are missing, stop at technical sequence testing, do not manufacture them.

Source-specific data and original patient images do **not** belong in GitHub. The probe's aggregate index receipt may be retained; archive bytes, raw member paths and patient material must not be committed. No purchase or large download is approved by this gate.

## Measured official-source result — November 2, 2026 UTC

The index-only cloud probe **succeeded** against the publisher's exact HTTPS URL. The verified ZIP central directory reports archive size **471,955,454 bytes**, **7,190 files** and **736,869 transferred bytes** in four exact-range requests. The first index-only probe left **123,633,993 bytes**. Two subsequent branch-push probes unintentionally repeated the same index request before the workflow was made manual-only. All three successful job logs independently report **736,869 bytes** each; total new index transfer **2,210,607 bytes**. The conservative cumulative source accounting is now **414,710,657 / 536,870,912 bytes**, leaving **122,160,255 bytes**. No pixel data were extracted in any of the three probes. The original successful index receipt remains unchanged.

- **Set 1:** 6,590 encrypted files: 3,295 candidate image files plus 3,295 path-indicated masks, 395,122,314 compressed bytes. **Nonsequential**, so not evidence of complete lesion intervals.
- **Set 2:** exactly 600 encrypted candidate image files, **75,733,598 compressed bytes** (75,744,545 uncompressed), with **zero separate mask/annotation files** identified in the ZIP directory. Its pixel bytes were **not downloaded** and its labels have **not been verified**.

All source members report ZIP encryption; the official public landing page posts the dataset-access password. Although Set 2's compressed bytes could fit the *remaining* transfer budget, the public index provides no validated frame-wise lesion truth. **Decision: NO-GO for a new pathology-interval benchmark based on Set 2 as currently released.** Do not exhaust the residual source budget on these images unless an independent annotation source is verified. The aggregate cloud source receipt is preserved at [`experiments/red-lesion-source/index-receipt.json`](../experiments/red-lesion-source/index-receipt.json); the [GitHub Actions index-only run](https://github.com/Kushrishi/capsule-review/actions/runs/41379518803) passed. No full-archive MD5/SHA match is claimed because the full 471.96-MB source was not downloaded.

Next scientifically justified action is to establish access to validated **frame-/interval-level** pathology labels and source-examination grouping (preferably Galar with an explicitly approved larger acquisition budget, or confirmed annotated Red Lesion Set 2 reference), and obtain domain-expert input before committing to a clinical pathology-retrieval model. Negative source-feasibility evidence is a valid stopping result; no new model has been trained.
